# Deferred, undecided, and different on purpose

The list the project keeps of what Python in JSC does not do. Three kinds of entry: **different** (follows from the design, and
stays), **experiment** (needs trying out before it can be decided), **deferred** (known work, not started or not finished).

## Different: follows from the design

| What                                         | Why, and what happens instead                                                                                                                                                                                                    |
| -------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Objects are not freed at the last `del`      | There are no reference counts. Finalizers and weak reference callbacks run at the first safe point after the collection that finds the object dead; `gc.collect()` forces it; everything left is finalized at exit. See README.   |
| `sys.getrefcount`, `gc.get_referrers`, ...   | Nothing to report. `getrefcount` returns a constant, `get_objects`/`get_referrers` are empty, `gc.collect()` returns 0.                                                                                                          |
| `__del__` given to a class after instances exist | Instances register for finalization when they are made.                                                                                                                                                                       |
| All NaNs are one object                      | A NaN is an immediate value: `float('nan') is float('nan')`, so `x in [x]`-style identity shortcuts see any NaN as the same. The sign and payload of a NaN are not kept.                                                          |
| `id()` of numbers, `is` on numbers and strs  | Numbers are immediates: equal ints and floats are identical. Equal strs need not be.                                                                                                                                             |
| A whole `float` becomes a number in JS       | `2.0` handed to JS is `2`, and comes back as the int `2`. Inside a list JS can see the cell that holds it.                                                                                                                        |
| An int beyond 2^53 is a BigInt in JS         | And a BigInt from JS is an int in Python.                                                                                                                                                                                         |
| `None` is `undefined` in JS                  | And both `undefined` and `null` are `None` in Python. So `JSON.stringify({"a": None})`, given a dict, leaves `a` out, as it does for any property that is `undefined` (in a list it is `null`); `json.dumps` writes `null`. |
| `bytecode`: `co_code`, `dis`, `.pyc`         | The bytecode is JSC's. `co_code` is empty, `dis` shows nothing. A `.pyc` file, and what `marshal` writes for a code object, is read by the build of Bun that wrote it and by nothing else, and CPython's are not read here. What it writes for other values is read by CPython and the other way round, but is not the same bytes from version 3 on: which objects CPython numbers for reference depends on reference counts.                                                                                            |
| Comparisons in JS are true or false          | `a < b` in JS is the truth of what `__lt__` returns.                                                                                                                                                                              |
| JS has no `//`, `@`, `+=` of its own         | `a += b` in JS is `a = a + b` (`__add__`, not `__iadd__`). Floor division and matrix multiplication are method calls.                                                                                                             |

## Experiments

| What                              | The question                                                                                                                                                                                                                                       |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Whole floats as heap numbers      | Teach JSC a non-object "heap number" cell that `typeof`, `===`, `Map` keys and the JITs treat as a number, so that a `PyFloat` inside a list is indistinguishable from a number in JS. Every place that enumerates the primitive cell kinds is touched. |
| Lists of floats as double arrays  | A list that holds only floats could use JSC's `ArrayWithDouble`, marked by its Structure as "every element is a float": no cells, and JS sees plain numbers. An int stored by JS becomes a float.                                                    |
| dict as a JS object or Map        | `PyDict` is its own hash table (keys compare with `__eq__`/`__hash__`, insertion order, any hashable key). JS sees it as an exotic object. Whether it should also be a `Map` to JS is open.                                                          |
| Prompt finalization               | How far escape analysis or scoped regions (`with`, function exit) can bring back "freed when the function returns" for objects that provably do not escape.                                                                                         |
| JIT                               | Python runs in the LLInt, with fast paths and inline caches there (README, Code). No Baseline, DFG or FTL. The caches are monomorphic.                                                                                                              |
| Generators without leaving the interpreter | Each resumption enters the VM anew from C++ and saves and restores registers one by one through a scope object: 2.5 times CPython's cost. Design: the bookkeeping of `PyGenerator::resume` moves into the body (an instruction at its start, one in place of `ret`), registers are saved in bulk, `op_py_for_iter` makes the frame and calls the body, and the unwinder does the cleaning up when the body raises. |
| Recursion limit                   | `sys.setrecursionlimit` against the real stack limit of JSC.                                                                                                                                                                                        |

## Deferred

| What                                      | State                                                                                                                                                                  |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Threads                                   | Done, with a GIL: see README. No free threading. Holes, worst first: `_sqlite3` never lets go of the GIL and SQLite has a mutex per connection, so two threads that share a connection can deadlock (one is switched out inside a user function, the other blocks on the mutex with the GIL), and `check_same_thread` is ignored; JS code never yields the GIL, so a long computation in JS starves the threads; a thread that reads into or writes from the memory of WebAssembly keeps the GIL in the system call (that memory cannot be pinned); what other threads leave to the main thread (dead objects of the host, a termination) waits while the main thread is in a long system call; a blocking call costs about 0.4 µs more while another thread exists; zlib and hashlib keep the GIL; `settrace`/`setprofile` are not per thread; no more than 4 global objects with Python in one VM; POSIX only, tested on Linux only. |
| `fork`, `multiprocessing`, subinterpreters| No `os.fork`, no subinterpreters. `multiprocessing` has the start method `spawn` and no other, as on Windows (Bun's `_bun_import.py` takes `fork` and `forkserver` out of `multiprocessing.context` when it is imported; `get_context("fork")` still gives a context, which starts no process): `Process`, `Pool`, `Queue`, `Manager`, locks, `ProcessPoolExecutor` work. `Value` and `Array` need `_ctypes`. `os.spawnv` and its kin, which `os.py` writes with `fork`, are functions of `posix` here. |
| Subprocesses                              | `_posixsubprocess.fork_exec` is complete but for `preexec_fn`, which raises `RuntimeError`: no code of the engine can run in a forked child.                              |
| Sockets                                   | Addresses of `AF_INET`, `AF_INET6`, `AF_UNIX`, `AF_NETLINK`; other families have their constants only. No `sendmsg_afalg`, no `CAPI`. Names that are not ASCII need `encodings.idna`. |
| `ssl`                                     | Done, on Bun's BoringSSL (`src/jsc/bindings/python/BunPythonSsl.cpp` in Bun), which is not OpenSSL. `ssl.OPENSSL_VERSION` is the library's own "OpenSSL 1.1.1 (compatible; BoringSSL)". Not there, and said so (`HAS_*` is False, `NotImplementedError`, or the library's refusal as `SSLError`): post-handshake authentication, external PSKs in TLS 1.3, choosing the cipher suites of TLS 1.3 (`set_ciphersuites`), the signature algorithm of one's own side (`client_sigalg()` on a client), security levels (`@SECLEVEL=n` in a cipher string is refused, `security_level` is 0), finite-field DH (`load_dh_params` reads the file and that is all), compression, kernel TLS, renegotiation. Options that the library has no use for are 0 (`OP_NO_COMPRESSION`, `OP_NO_SSLv3`, `OP_SINGLE_DH_USE`, ...). The reasons of errors have the library's names, and their texts are those names in lower case. `session_stats()` counts handshakes and hits itself; misses, timeouts and `cache_full` stay 0. `ticket_lifetime_hint` of a TLS 1.3 session is 0. A context has a certificate for each kind of key, as in OpenSSL, but what `set_server_sigalgs()` and `set_client_sigalgs()` say about one's own signatures binds only the one loaded last. Certificates, keys and CA files are read by the library from the real file system, not from the virtual directory in the executable. The library runs with the GIL held: only waiting for the socket lets other threads in. `set_default_verify_paths()` is `$SSL_CERT_FILE`, `$SSL_CERT_DIR` and the system's OpenSSL directory (`/etc/ssl`); where neither variable is set and that directory has no `cert.pem` and no hashed certificates, the roots that come with Bun. No Windows (`enum_certificates`). |
| `mmap`                                    | The memory is that of an `ArrayBuffer`, so at most 4 GiB in one mapping.                                                                                                  |
| C API (`abi3t`), extension modules        | Not started. `PyObject*` would be a handle on a `JSValue`. No numpy until then.                                                                                            |
| Package manager (`bun install` from PyPI) | Not started, by decision: the language first.                                                                                                                             |
| Event loop                                | Done, see README. Missing: `import asyncio` is needed for any coroutine that JS awaits, even one that never suspends, and is slow to import; no `_asyncio` accelerator; `time.sleep`, `os.read`, `waitpid` and lock waits block the thread without turning the host's loop; Windows. |
| Standard library in the binary            | A read-only virtual directory (`runtime/PyVirtualFiles.h`). It has no directory descriptors (`os.fwalk`, `dir_fd`), no `chdir`, and other programs cannot see it.          |
| Start-up and import speed                 | Compiled code is cached (README, Imports). What is left of start-up is making the built-in types and running `importlib`, `site` and what they import. Not done: the code of the standard library could be made when Bun is built and be part of the executable, so that there is no first run; directories of builds that are gone stay in the user's cache directory; a function that is defined decodes all of its `CodeInfo`, names of variables included, though most of it is only needed by introspection. |
| Python importing JS                       | Done, see README. Missing: `import a.b` for a subpath of a JS package (use `importlib.import_module("a/b")`), modules with top-level await (`require()` refuses them), the name of the module in `ImportError` messages. |
| Output of two languages                   | `console.*` first writes what `print()` has left in the buffers of `sys.stdout` and `sys.stderr`, so the order is kept when they are pipes or files. `process.stdout.write()` and `Bun.write(Bun.stdout, ...)` do not. |
| Iterators of JS                           | `for` and `async for` in Python take items from a JS iterator as they go. Leaving the loop early does not call the iterator's `return()`. |
| Too many open files                       | A system call that fails with `EMFILE` should collect, finalize and try again: files nobody can reach are still open until a collection finds them.                          |
| Exception scope verification              | `BUN_JSC_validateExceptionChecks=1` (Bun's ASAN CI sets it) fails as soon as the runtime starts. The C++ of the runtime has to be gone through.                            |
| Signals                                   | Handlers run at safe points (`VMTraps::NeedPythonCalls`), where a system call is interrupted, and between turns of the host's event loop. Not while JS code runs. `SIGPWR` is the engine's. No Windows. |
| Tracing and profiling                     | `sys.settrace`, `sys.setprofile`: stored, never called. `sys.monitoring` has its whole API and takes registrations, but no event ever fires. So no `pdb` (`python3 -m pdb x.py` never stops, and runs the program again and again), no `bdb`, no `coverage`, no `trace`. `cProfile` loads and reports nothing. |
| `tracemalloc`                             | Measures no memory: the allocators are the engine's, and most objects are made by a few instructions inline, where there is no place for a hook. `get_traced_memory()` is `(0, 0)` and a snapshot is empty. What it knows, while it is on, is where the objects were made that have a finalizer (files, sockets, instances of classes with `__del__`): `get_object_traceback()`, and so the "Object allocated at" of a `ResourceWarning`. |
| `faulthandler`                            | `enable()` takes the place of the host's handlers of `SIGSEGV`, `SIGFPE`, `SIGABRT`, `SIGBUS`, `SIGILL`: the Python stacks of all threads are written and the process dies of the signal, without Bun's crash report. A fault in code the engine generated goes to the engine first (WebAssembly's bounds checks). No C stack, no list of extension modules, no `_stack_overflow`. |
| Audit events                              | `sys.audit`, `sys.addaudithook`, and the events of what is implemented in C++ (`open`, `os.*`, `socket.*`, `import`, `compile`, `exec`, `sys.*`, `gc.*`, `marshal.*`, `pickle.find_class`, `sqlite3.connect`, ...). Missing: `cpython.run_*`, `code.__new__`, `function.__new__`, `object.__getattr__` of frames and generators, `sqlite3.enable_load_extension` and `load_extension`, `ctypes.*`. There are no hooks for the host (`PySys_AddAuditHook`). |
| `unicodedata`                             | ICU's data, brought up to the Unicode version of this Python by tables (`tools/make_unicodedata_overlay.py`) of what Bun's ICU, which is older, does not know. An ICU that is *newer* than Python's Unicode would show through. Identifiers are normalized (NFKC) by ICU alone. |
| A native module imported again            | One that is taken out of `sys.modules` and imported again is the same object, not a new one: its types are made once.                                                      |
| Frames                                    | Frame objects are snapshots. `f_locals` of a finished frame is empty; writing to `f_locals` or `f_lineno` has no effect.                                                   |
| Traceback carets                          | Column ranges are not recorded (`co_positions`), so tracebacks have no `^^^^` lines.                                                                                       |
| `f.__code__ = other`                      | Only what `types.coroutine` needs.                                                                                                                                        |
| Strings                                   | Indexing a str with astral characters is O(n). A surrogate pair written as two escapes is one character. Hashes are 24 bits wide in places.                                |
| `bun build` of Python                     | To the bundler a `.py` file is what it always was, an asset (the `file` loader); `with { type: "python" }` is refused. No `--compile` of a Python program.                  |
| When a `.py` module imported by JS runs   | When the module loader fetches it, not when ES evaluation reaches it, because its exports are only known once it has run (Bun's CommonJS modules imported by ES modules are the precedent). So it runs before JS modules imported earlier in the same file, and even if the graph then fails to link. The names a module binds at the top level are known from its symbol table: with those as the export names the body could run at the right time. |
| AOT-compiled JS (`--aot`)                 | Its type reasoning has not been taught that operators on Python objects are overloaded. Do not mix.                                                                        |
| Call sites in Python code with many callees | Only monomorphic inline caches; a second callee takes the slow path each time.                                                                                          |
| Command line (`python3`)                  | Done, see README. Accepted without effect: `-b` (no `BytesWarning` is ever issued), `-d`, `-R` and `PYTHONHASHSEED` (hashes do not depend on a seed), `-X frozen_modules`, `-X gil`, `-X perf`, `-X presite`, `-X showrefcount`, `-X no_debug_ranges`, `-X utf8=0` (the flag only: everything is UTF-8, no locale is consulted), `PYTHONMALLOC`, `PYTHONCOERCECLOCALE`. `-v` prints what `importlib` prints. `sys.argv[0]` of `bun main.py` is the resolved path, not what was typed. No `sys.path` entry for `python315.zip` or `lib-dynload`. Arguments and file names that are not UTF-8 are not kept byte for byte (no `surrogateescape` on the command line). |
| Interactive interpreter                   | No `readline` module: without `_pyrepl` (`PYTHON_BASIC_REPL`, no terminal) there is no line editing and no history. Tasks that a statement leaves behind run only while a later statement awaits. `bun` without arguments is not a Python prompt. |
| `python3` link                            | `sys.executable` of `bun main.py` is a symbolic link in `/tmp/bun-python-<uid>-<hash of the path of Bun>`, made on demand. It is not on `PATH` (a child that runs `python3` by name gets the system's). Virtual environments made by `venv` link to it, so they die with the temporary directory. `ensurepip` is untested. None of it on Windows. |
| CPython's test suite                      | See README, "Testing". Not run at all: the C API (`test_capi`, `test_cext`, `test_cppext`, `test_ctypes`, `test_embed`), Tk, tools of CPython's repository, Windows, Android, iOS. Skipped by themselves for want of `_testcapi`, `_testinternalcapi`, `_testmultiphase` (all of `test_importlib`'s helpers import it), `_interpreters`, `fork`: 167 modules, 58 of which CPython skips too. |
| Windows                                   | `posix`, `time`, `_io`, threads and Bun's `BunPython.cpp` are written for POSIX and do not compile there: until that is done, or Python is compiled out on Windows, the branch breaks the Windows build. |
| Docstrings of native functions            | `NativeDef` has no field for them.                                                                                                                                        |
